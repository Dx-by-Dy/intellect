# Разбор базовых задач

Решения лежат в [`solutions/`](solutions/), тесты в [`tests/`](tests/). Проверить всё одной командой:

```bash
./run_tests.sh        # все решения
./run_tests.sh 05 07  # только 05 и 07
```

Скрипт компилирует каждое решение (`g++ -std=c++17`) и проверяет его чекером [`tests/check.py`](tests/check.py). Чекер не сравнивает текст, а проверяет ответ по условию: в задачах с путями и компонентами правильных ответов бывает несколько.

Задачи идут от простого к сложному. Каждая следующая добавляет к предыдущей одну новую идею.

| № | Задача | Новая идея |
|---|---|---|
| 1 | inf 462 + inf 464 | матрица: каждое ребро записано дважды |
| 2 | inf 164 Обход в глубину | DFS по матрице |
| 3 | inf 111540 Компоненты связности | списки смежности, внешний цикл, большие `n` |
| 4 | inf 160 Путь | BFS, `dist`, `par`, восстановление пути |
| 5 | inf 161 Один конь | неявный граф на доске |
| 6 | CSES 1192 Counting Rooms | компоненты на клетчатом поле |
| 7 | inf 165 Банкет | двудольность покраской |
| 8 | inf 166 Построение | топологическая сортировка |
| — | CSES 1667 Message Route | решение для самостоятельного сравнения с «Путь» |

## 1. Подсчёт рёбер и матрица → список рёбер (inf 462, inf 464)

Решения: [`01_inf462_edges_count.cpp`](solutions/01_inf462_edges_count.cpp), [`02_inf464_matrix_to_edges.cpp`](solutions/02_inf464_matrix_to_edges.cpp)

**Идея.** В неориентированном графе ребро `u–v` даёт две единицы: `a[u][v]` и `a[v][u]`. Поэтому:

- в 462 число рёбер равно сумме всех элементов матрицы, делённой на 2;
- в 464 печатаем только клетки над диагональю (`j > i`), тогда каждое ребро выводится один раз.

**Типичные ошибки.**
- Ответ в 462 в 2 раза больше правильного: забыли поделить.
- В 464 каждое ребро напечатано дважды (`1 3` и `3 1`): цикл по `j` начат с 1, а не с `i + 1`.

**Подумайте.** Что изменится для ориентированного графа (задачи 463, 466)? Ответ: делить не нужно, перебирать нужно всю матрицу.

## 2. Обход в глубину (inf 164)

Решение: [`03_inf164_dfs.cpp`](solutions/03_inf164_dfs.cpp)

**Идея.** Ровно DFS из лекции. Отличие одно: граф задан матрицей, поэтому вместо `for (int to : g[v])` перебираем все `to` от 1 до `n` и проверяем `a[v][to] == 1`.

Ответ — количество вершин, в которые зашёл DFS. Считаем счётчиком при входе в вершину.

**Сложность.** С матрицей каждый вызов `dfs` перебирает `n` вершин, всего `O(n²)`. При `n ≤ 100` это 10 000 операций.

**Типичные ошибки.**
- Не помечают вершину в начале `dfs`, программа зацикливается.
- Не считают саму стартовую вершину (в условии: «считая эту вершину»).

## 3. Компоненты связности (inf 111540)

Решение: [`04_inf111540_components.cpp`](solutions/04_inf111540_components.cpp)

**Идея.** Внешний цикл по всем вершинам. Если вершина ещё не посещена, запускаем из неё обход: он соберёт ровно одну компоненту. Вершины компоненты складываем в `vector`, потом печатаем.

**На что обратить внимание.**
- `n` и `m` до 10⁵. Матрица 10⁵ × 10⁵ — это 10¹⁰ ячеек, она не поместится. Это первая задача, где нужны **списки смежности**.
- Граф может быть цепочкой из 10⁵ вершин. Рекурсивный DFS тогда уходит на глубину 10⁵ и на некоторых системах падает с переполнением стека. В решении DFS написан **с явным стеком** (`vector<int> st`): это та же идея, только стек мы держим сами. Можно и BFS, для компонент неважно, какой обход.
- Условие не запрещает петли и кратные рёбра. Обход с ними работает без изменений.
- Быстрый ввод: `ios::sync_with_stdio(false); cin.tie(nullptr);`.

## 4. Путь (inf 160)

Решение: [`05_inf160_path.cpp`](solutions/05_inf160_path.cpp)

**Идея.** Кратчайший путь по числу рёбер ищем BFS. Кроме `dist` заводим `par[v]` — вершину, из которой BFS впервые пришёл в `v`. Путь восстанавливаем от финиша назад: `t, par[t], par[par[t]], …, s`, затем разворачиваем.

**Почему BFS даёт кратчайший путь.** Вершины достаются из очереди в порядке неубывания `dist`: сначала все на расстоянии 0, потом все на 1, потом на 2. Когда вершина впервые попадает в очередь, раньше до неё дойти было нельзя.

**Особые случаи из условия.**
- Нет пути: вывести `-1`.
- Старт совпадает с финишем: вывести только `0`, без пути.

**Типичные ошибки.**
- Помечают вершину при извлечении из очереди, а не при добавлении: одна вершина попадает в очередь много раз.
- Выводят путь задом наперёд: забыли `reverse`.
- Использовали DFS. Он находит какой-то путь, но не обязательно кратчайший. Это видно на графе «Пример» на странице лекции: DFS идёт из 1 в 3 через 2 и 4.

## 5. Один конь (inf 161)

Решение: [`06_inf161_knight.cpp`](solutions/06_inf161_knight.cpp)

**Идея.** Граф здесь не дан явно. Вершина — клетка доски `(x, y)`, рёбра — ходы коня. Хранить граф не нужно: соседей получаем через массивы сдвигов

```cpp
int dx[8] = {1, 2, 2, 1, -1, -2, -2, -1};
int dy[8] = {2, 1, -1, -2, -2, -1, 1, 2};
```

и отбрасываем клетки за пределами доски. `dist` и `par` становятся двумерными, `par` хранит пару координат. В остальном это тот же BFS, что в задаче «Путь».

**Подумайте.** Сколько вершин и рёбер в этом графе при `n = 20`? Ответ: 400 вершин, у каждой не больше 8 соседей.

## 6. Counting Rooms (CSES 1192)

Решение: [`08_cses1192_counting_rooms.cpp`](solutions/08_cses1192_counting_rooms.cpp)

**Идея.** Задачи 3 и 5 вместе: компоненты связности (внешний цикл по всем клеткам) в графе на клетчатом поле (4 соседа через `dx`, `dy`).

**На что обратить внимание.** Поле до 1000 × 1000, то есть до 10⁶ клеток. Если всё поле — одна извилистая комната, рекурсивный DFS уйдёт на глубину порядка 10⁶ и упадёт. Поэтому в решении каждая комната обходится BFS: на больших полях рекурсивный DFS опасен.

## 7. Банкет (inf 165)

Решение: [`07_inf165_banquet.cpp`](solutions/07_inf165_banquet.cpp)

**Идея.** Гости — вершины, «не ладят» — рёбра. Нужно разбить вершины на две группы так, чтобы каждое ребро шло между группами. Это проверка графа на **двудольность**.

Красим DFS: стартовую вершину в цвет 1, каждого непокрашенного соседа в противоположный цвет (`3 - c`). Если встретили покрашенного соседа того же цвета, рассадить нельзя.

**На что обратить внимание.**
- Граф может быть несвязным: нужен внешний цикл, как в задаче 3.
- Граф двудолен тогда и только тогда, когда в нём нет цикла нечётной длины. Треугольник 1–2–3 — простейший пример `NO`.

## 8. Построение (inf 166)

Решение: [`09_inf166_topsort.cpp`](solutions/09_inf166_topsort.cpp)

**Идея.** Пара `A B` — ориентированное ребро `A → B` («A стоит раньше B»). Нужно расставить вершины так, чтобы все рёбра шли слева направо. Это **топологическая сортировка**, она существует, только если в графе нет цикла.

DFS с тремя цветами:
- 0 — ещё не заходили;
- 1 — зашли, но не вышли (вершина сейчас в стеке вызовов);
- 2 — вышли.

Ребро в вершину цвета 1 означает цикл. Если циклов нет, выписываем вершины в момент выхода из `dfs`. К этому моменту все вершины, которые должны стоять после `v`, уже выписаны. Развернув список, получаем ответ.

На странице лекции такой граф можно посмотреть, выбрав пресет «Ориентированный».
