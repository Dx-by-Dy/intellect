# C++ для этого занятия: шпаргалка для того, кто знает C и Rust

В решениях используется маленькое подмножество C++17. Ниже всё, что встречается в коде лекции и разбора, с аналогами из C и Rust.

## Заголовок и пространство имён

```cpp
#include <bits/stdc++.h>   // подключает всю стандартную библиотеку (только GCC)
using namespace std;       // чтобы писать vector, а не std::vector
```

Так пишут на олимпиадах, в промышленном коде так не делают. `bits/stdc++.h` есть в GCC (informatics, Codeforces, CSES). В MSVC и clang на macOS его нет.

## Ввод и вывод

```cpp
int n, m;
cin >> n >> m;               // scanf("%d %d", &n, &m) — без & и форматной строки
cout << n << ' ' << m << '\n';
```

- `cin >> x` пропускает пробелы и переводы строк, как `scanf("%d")`.
- Строку без пробелов читают так: `string s; cin >> s;`.
- `'\n'`, а не `endl`: `endl` ещё и сбрасывает буфер, на большом выводе это медленно.
- На больших входных данных в начале `main` добавляют:

  ```cpp
  ios::sync_with_stdio(false);
  cin.tie(nullptr);
  ```

  Это отключает синхронизацию с `stdio`, `cin` становится быстрым как `scanf`. После этого нельзя смешивать `cin` и `scanf` в одной программе.

## `vector` — динамический массив

Аналог: `Vec<T>` в Rust, `malloc` + `realloc` в C.

```cpp
vector<int> a(n);            // n нулей                        | vec![0; n]
vector<int> d(n + 1, -1);    // n + 1 элементов, все -1        | vec![-1; n + 1]
vector<int> path;            // пустой                         | Vec::new()
path.push_back(5);           // добавить в конец               | push(5)
path.back();                 // последний элемент              | last()
path.pop_back();             // удалить последний (ничего не возвращает!)
path.size();                 // длина, тип size_t              | len()
path.empty();                // пустой ли                      | is_empty()
reverse(path.begin(), path.end());   //                        | path.reverse()
sort(path.begin(), path.end());      //                        | path.sort()
d.assign(n + 1, 0);          // переразметить: n + 1 нулей
g.resize(n + 1);             // изменить размер, новые элементы — по умолчанию
```

- `a[i]` **не проверяет границы**, как массив в C. Выход за границу — неопределённое поведение, а не паника. `a.at(i)` проверяет, но так обычно не пишут.
- `vector` копируется при присваивании и при передаче в функцию по значению (как `clone()` в Rust). Поэтому графы объявляют глобальными или передают по ссылке: `void f(vector<int>& a)`.

### Двумерный вектор

```cpp
vector<vector<int>> a(n + 1, vector<int>(n + 1));   // матрица (n+1) x (n+1) из нулей
vector<vector<int>> g(n + 1);                        // n + 1 пустых списков
g[u].push_back(v);                                   // добавить v в список соседей u
```

Это `Vec<Vec<i32>>`. Внутренние векторы независимы и могут иметь разную длину — это и есть списки смежности.

## Цикл по контейнеру

```cpp
for (int to : g[v]) { ... }        // for &to in &g[v]  (копия int — дёшево)
for (auto& comp : comps) { ... }   // for comp in &mut comps  — ссылка, без копирования
```

`auto` — вывод типа, как `let` без аннотации. `auto&` — ссылка, `auto` без `&` — копия элемента.

## `pair` и structured bindings

```cpp
pair<int, int> p = {3, 5};       // (i32, i32)
p.first; p.second;               // p.0, p.1
queue<pair<int, int>> q;
q.push({x, y});
auto [x, y] = q.front();         // let (x, y) = ...  (C++17)
```

## `queue` — очередь для BFS

Аналог: `VecDeque` в Rust.

```cpp
queue<int> q;
q.push(s);          // в конец            | push_back
q.front();          // первый элемент     | front()
q.pop();            // удалить первый, НИЧЕГО НЕ ВОЗВРАЩАЕТ
q.empty();
```

Главное отличие от Rust: `pop()` не возвращает элемент. Поэтому всегда пишут две строки:

```cpp
int v = q.front();
q.pop();
```

У `stack<int>` то же самое: `top()`, затем `pop()`. В решениях вместо `stack` используется `vector` с `back()` и `pop_back()`.

## `string`

```cpp
vector<string> a(n);
for (auto& row : a) cin >> row;    // читаем n строк поля
a[i][j] == '#'                     // символ — тип char, как в C
```

## Глобальные переменные и рекурсия

В решениях граф и массив `used` глобальные, а `dfs` — обычная рекурсивная функция, как в C:

```cpp
vector<vector<int>> g;
vector<bool> used;

void dfs(int v) {
    used[v] = true;
    for (int to : g[v])
        if (!used[to])
            dfs(to);
}

int main() {
    ...
    g.resize(n + 1);
    used.assign(n + 1, false);
}
```

Глобальные `vector` создаются пустыми, размер задаём в `main`, когда узнали `n`.

**Глубина рекурсии.** Стек программы обычно 8 МБ (Linux) или 1 МБ (Windows). Цепочка из 10⁶ вершин в рекурсивном DFS переполнит стек и программа упадёт. Тогда пишут BFS или DFS с явным стеком (`vector<int> st`).

## Что может удивить знающего C

| C++ | Что происходит |
|---|---|
| `int` | 32 бита, переполняется молча, как в C. Большие ответы — `long long` (`i64`). |
| `vector<bool>` | Упакован по биту на элемент. Работает, но `&used[i]` взять нельзя. |
| `a.size() - 1` при пустом `a` | `size_t` беззнаковый: получится огромное число, как в C. |
| `3 - c` | Удобный способ переключать цвет 1 ↔ 2 в задаче о двудольности. |
| `INT_MAX`, `LLONG_MAX` | Как в `limits.h`, подключены через `bits/stdc++.h`. |

## Компиляция и запуск

```bash
g++ -std=c++17 -O2 -Wall -o sol sol.cpp
./sol < input.txt
```

Флаги для отладки, которые ловят выход за границы и неопределённое поведение (аналог debug-сборки в Rust):

```bash
g++ -std=c++17 -g -fsanitize=address,undefined -D_GLIBCXX_DEBUG -o sol sol.cpp
```
