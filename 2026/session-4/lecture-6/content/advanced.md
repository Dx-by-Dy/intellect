# Продвинутые алгоритмы на деревьях

Здесь три способа обрабатывать запросы в дереве. Во всех примерах дерево неориентированное, расстояние измеряется числом рёбер, а корень, когда он нужен, — вершина 1.

| Что требуется | Метод | Стоимость после подготовки |
| --- | --- | --- |
| Много запросов на ближайшего общего предка (LCA) | Эйлеров обход и разреженная таблица | `O(1)` на запрос |
| Сумма на пути и изменения значений в вершинах | Разложение на тяжёлые цепи и дерево отрезков | `O(log²(n + 1))` на запрос, `O(log(n + 1))` на обновление вершины |
| Расстояние до ближайшей отмеченной вершины, отметки только добавляются | Центроидная декомпозиция | `O(log(n + 1))` на операцию с заранее посчитанными расстояниями |

## LCA через эйлеров обход и RMQ { #euler-rmq }

!!! example "Прикладная задача"
    По двум папкам архиватор должен быстро находить самую глубокую папку, которая содержит обе. Если одна из заданных папок содержит другую, ответом будет она сама. Структура архива постоянна.

В дереве папок это **ближайший общий предок**, или LCA. Данные для запросов можно подготовить заранее.

Обойдём дерево в глубину (DFS). Запишем вершину при первом входе в неё и при каждом возврате к ней после обхода ребёнка. Получим `2n − 1` записей: одну для старта и ещё по одной после каждого прохода по ребру вверх или вниз. Запомним `first[v]` — позицию первого появления `v`.

```text
Обход    1  2  4  2  5  2  1  3  6  7  6  8  9  8  6  10  6  3  1
Глубина  0  1  2  1  2  1  0  1  2  3  2  3  4  3  2   3  2  1  0
```

Между первыми появлениями двух вершин обход посещает их ближайшего общего предка. Он успевает дойти до второй вершины, прежде чем выйдет из поддерева предка. Поэтому вершина минимальной глубины на отрезке и есть LCA. Для `(7, 9)` включаем оба конца и получаем `7, 6, 8, 9`. Минимальная глубина равна 2 у вершины 6.

Так запрос LCA превращается в **RMQ** (range minimum query), то есть поиск минимума на отрезке. Разреженная таблица хранит для каждой позиции `i` и длины `2ʲ` вершину минимальной глубины на отрезке, который начинается в `i`. Строку для длины `2ʲ` строим, сравнивая минимумы двух соседних половин длины `2ʲ⁻¹`.

Для запроса `[l, r]` берём наибольшую степень двойки `len`, которая не превосходит длину отрезка. Сравниваем минимумы двух блоков длины `len`. Один начинается в `l`, другой заканчивается в `r`. Блоки покрывают весь отрезок, и их пересечение не влияет на минимум.

Построение занимает `O(n log(n + 1))` времени и памяти. Если заранее посчитать целые логарифмы длин, запрос занимает `O(1)`.

??? question "Можно ли таким же способом отвечать на запрос суммы двумя перекрывающимися блоками?"
    Элементы из пересечения тогда сложатся дважды. Для суммы без изменений можно использовать префиксные суммы.

## Разложение на тяжёлые цепи { #hld }

!!! example "Прикладная задача"
    Между пунктами сбора макулатуры проложены дорожки, образующие дерево. Каждый пункт сообщает текущее число коробок. Машина едет по кратчайшему маршруту от одного пункта до другого и забирает коробки во всех пунктах на её пути, включая оба конца. Нужно быстро оценивать загрузку для разных маршрутов и учитывать обновления числа коробок.

DFS записывает поддерево подряд, если записывать каждую вершину при входе. Подберём порядок DFS, в котором любой путь разбивается на небольшое число отрезков.

У каждой вершины с детьми выберем ребёнка с наибольшим размером поддерева. Ребро к нему назовём **тяжёлым**, остальные рёбра к детям — **лёгкими**. Тяжёлые рёбра образуют непересекающиеся цепи, включая цепи из одной вершины. Этот метод называется **heavy-light decomposition**, или HLD.

1. Найдём размеры поддеревьев и выберем тяжёлого ребёнка для каждой вершины. При равенстве размеров подойдёт любой.
2. Выполним DFS, всегда заходя в тяжёлого ребёнка первым. Присвоим каждой вершине позицию `pos[v]` и запомним верхнюю вершину её цепи `head[v]`. Каждая цепь займёт непрерывный отрезок позиций.
3. Построим дерево отрезков по значениям вершин в этом порядке.

В дереве на схеме одна тяжёлая цепь — `1 → 3 → 6 → 8 → 9`. При равенстве размеров детей 2 выберем 4. Тогда `2 → 4` — другая тяжёлая цепь. Путь от 4 до 9 состоит из частей `4 → 2` и `1 → 3 → 6 → 8 → 9`. Если изначально в каждом пункте столько коробок, каков его номер, два запроса к дереву отрезков дадут `(4 + 2) + (1 + 3 + 6 + 8 + 9) = 33` коробки. Если число коробок в пункте 6 изменится на 20, результат того же запроса станет 47.

Для произвольных `u` и `v`, пока `head[u] ≠ head[v]`, выбираем вершину с более глубокой головой цепи. Пусть это `u`. Добавляем сумму на отрезке от `pos[head[u]]` до `pos[u]` включительно и заменяем `u` на `parent[head[u]]`. Когда головы совпадут, добавляем сумму между текущими позициями включительно. Каждый шаг снимает часть пути, а последняя часть содержит LCA.

При спуске по лёгкому ребру размер поддерева уменьшается как минимум вдвое. У родителя есть тяжёлый ребёнок с поддеревом не меньше. Поэтому на каждом пути к корню есть `O(log(n + 1))` лёгких рёбер. Путь между двумя вершинами складывается из двух таких подъёмов до LCA. Получаем `O(log(n + 1))` отрезков и `O(log²(n + 1))` времени на запрос суммы. Обновление одной вершины занимает `O(log(n + 1))`. Подготовка и память для разложения и дерева отрезков — `O(n)`.

Выберите концы пути и количество коробок в вершине 6. Каждый шаг снимает один отрезок цепи и добавляет его сумму.
{: data-demo="hld" }

??? question "Как считать сумму весов рёбер вдоль пути?"
    Вес ребра храним в позиции его более глубокого конца. Когда снимаем целый отрезок до головы цепи включительно, её позиция учитывает лёгкое ребро к родителю. В последнем отрезке исключаем позицию более высокой вершины, то есть LCA.

## Центроидная декомпозиция { #centroid }

!!! example "Прикладная задача"
    Вдоль экотроп постепенно открывают пункты проката. Турист на любой остановке хочет знать, сколько участков пути нужно пройти до ближайшего открытого пункта. Приложение получает два типа запросов: открыть пункт в вершине или найти расстояние от заданной вершины до ближайшего работающего пункта. Пункты остаются открытыми.

**Центроид** дерева из `m` вершин — вершина, после удаления которой в каждой оставшейся компоненте не больше `⌊m/2⌋` вершин. В дереве на схеме подходит вершина 3. После её удаления получатся компоненты из 4 и 5 вершин.

Центроид можно найти за `O(m)`. Укореним рассматриваемое дерево в любой его вершине и вычислим размеры поддеревьев. Если у текущей вершины есть ребёнок с поддеревом больше половины, перейдём к нему. После перехода компонента со стороны родителя имеет размер `m − size[v]` и меньше половины. Поэтому достаточно продолжать спуск. Когда у текущей вершины нет ребёнка с поддеревом больше половины, она является центроидом.

Удалим центроид из рассматриваемого дерева и повторим процесс в каждой оставшейся компоненте. Центроид исходного дерева станет корнем **дерева декомпозиции**, а центроиды новых компонент — его детьми. На каждом уровне размер компоненты уменьшается хотя бы вдвое. Поэтому дерево декомпозиции имеет `O(log(n + 1))` уровней, а построение занимает `O(n log(n + 1))` времени.

Для каждой вершины `v` запомним пары из центроидного предка `c` и расстояния до него. В списке есть и сама вершина `v` с расстоянием 0. Чтобы заполнить эти списки, при выделении центроида обходим его текущую компоненту. Подготовка и память вместе со списками по-прежнему занимают `O(n log(n + 1))`.

- При открытии пункта в `v` для каждого её центроидного предка `c` обновим `best[c] = min(best[c], dist(c, v))`. Изначально все `best[c] = ∞`.
- В запросе для `u` берём минимум `dist(u, c) + best[c]` по её центроидным предкам. Если минимум остался бесконечным, открытых пунктов нет.

Почему ответ точный? Любая такая сумма описывает маршрут через `c` и не меньше настоящего расстояния до соответствующей открытой точки. Возьмём ближайший открытый пункт `v`. На первом уровне, где центроид `c` разделяет `u` и `v` на разные компоненты или совпадает с одной из этих вершин, путь между `u` и `v` проходит через `c`. Через него получаем верхнюю границу `dist(u, c) + best[c] ≤ dist(u, c) + dist(c, v) = dist(u, v)`. Вместе с нижней границей это даёт точный ответ.

Откроем пункт 7 и спросим расстояние из 9. Путь между ними проходит через центроид 6 компоненты `{6, 7, 8, 9, 10}`, поэтому получаем `dist(9, 6) + dist(6, 7) = 2 + 1 = 3`. Если затем откроется пункт 8, ближайший ответ для 9 станет равен 1. При заранее посчитанных расстояниях открытие и запрос занимают по `O(log(n + 1))`.

Выберите открытые пункты и вершину запроса. Сначала увидите, как выделяются её центроиды, затем проверите расстояние через каждый из них.

??? question "Что понадобится, если пункты могут закрываться?"
    Можно хранить для каждого центроида мультимножество расстояний до открытых пунктов. Тогда при закрытии удастся удалить одно нужное расстояние и сразу получить новый минимум. Открытие и закрытие займут `O(log²(n + 1))`, а запрос ближайшего пункта — `O(log(n + 1))`.
