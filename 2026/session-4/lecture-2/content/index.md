# Взвешенные графы и алгоритм Дейкстры

Прямой автобус едет 10 минут. Маршрут с двумя пересадками занимает 5 минут. Как найти самый быстрый путь, если на карте сотни остановок?

## Направление и вес ребра { #weights }

Пусть вершины — остановки, а поездка между двумя остановками — ребро. В ориентированном графе ребро `u → v`, или **дуга**, разрешает ехать из `u` в `v`. Для обратной поездки нужна отдельная дуга, и её вес может быть другим.

Во взвешенном графе у каждого ребра есть число — **вес**. В нашем примере это время поездки. Вес пути равен сумме весов его рёбер. Направление и вес задаются независимо, поэтому взвешенный граф может быть и неориентированным.

По числу рёбер выигрывает прямой маршрут S → T. По суммарному весу — S → A → B → T.
{: data-demo="path-criteria" }

!!! note "Связь с BFS"
    На [первом занятии](../lecture-1/#bfs) хватало считать рёбра. Если каждое ребро весит 1, число рёбер и вес пути совпадают. На схеме выше BFS нашёл бы прямой маршрут за 10 минут, хотя через `A` и `B` можно доехать за 5.

??? question "Из U можно попасть в S. Можно ли из S попасть в U?"
    Нет. Из U выходит одна стрелка, а входящих стрелок у U нет.

??? question "На клетчатом поле из первого занятия вход на клетку стоит число, записанное в ней. Как задать вес перехода?"
    Берём число в клетке назначения. Обратный ход существует, если обе клетки проходимы, но его вес равен числу в другой клетке. Получаются две встречные дуги с весами, которые могут различаться.

## Как хранить взвешенный граф { #store }

Во вводе дугу обычно задают тройкой `u v w`. В список `g[u]` кладём пару `{v, w}`. Если ребро неориентированное, добавляем ещё `{u, w}` в `g[v]`.

```text title="Списки смежности малого графа"
g[S] = [{T, 10}, {A, 2}, {B, 6}]
g[A] = [{B, 1}]
g[B] = [{T, 2}]
g[T] = []
g[U] = [{S, 1}]
```

??? question "Как в матрице смежности отличить ребро веса 0 от отсутствующего?"
    Договориться об отдельной отметке для отсутствующего ребра, например `−1` в графе с неотрицательными весами. Если нужно хранить в ячейке все параллельные рёбра, одного числа тоже недостаточно. Для поиска только минимального веса пути хватит наименьшего веса между этой парой вершин в данном направлении.

## Что спрашивают в задаче о кратчайшем пути { #shortest }

**Расстояние** из `s` в `t` — наименьший вес пути из `s` в `t`. Если пути нет, обозначим расстояние символом `∞`. В графе с неотрицательными весами от старта до него самого всегда 0. Это вес пустого пути.

| Постановка | Пример |
| --- | --- |
| Из одной вершины в другую | Даны `s` и `t`. За сколько минут можно доехать от школы до вокзала? |
| Из одной вершины во все | Дана только `s`. Каковы расстояния от школы до каждой остановки? |
| Между всеми парами | Нужны расстояния для всех упорядоченных пар вершин. В ориентированном графе направление поездки имеет значение. |

Уточните, достаточно ли вывести расстояние или нужно перечислить вершины маршрута. Несколько путей могут иметь одинаковый минимальный вес. Если условие разрешает любой из них, достаточно запомнить одного предшественника для каждой вершины.

??? question "Есть 100 запросов до разных финишей, а старт у всех один. Сколько запусков Дейкстры понадобится?"
    Один полный запуск из общего старта. Из массива расстояний можно ответить на каждый запрос.

## Алгоритм Дейкстры по шагам { #dijkstra }

Пусть **все веса неотрицательны**. В `dist[v]` храним вес лучшего пути из `s` в `v` из тех, что уже нашли. В начале `dist[s] = 0`, у остальных вершин `dist[v] = ∞`.

1. Из ещё не обработанных вершин выбираем `v` с наименьшей оценкой `dist[v]`. Если конечных оценок больше нет, заканчиваем. Если минимальных несколько, подойдёт любая из них.
2. Фиксируем расстояние до `v`. Для каждой дуги `v → to` веса `w` проверяем путь через `v`.
3. Если `dist[v] + w < dist[to]`, записываем меньшую оценку в `dist[to]` и предшественника `v` в `par[to]`. Проверку с возможным обновлением называют **релаксацией ребра**. Возвращаемся к выбору вершины после проверки всех исходящих дуг.

Пошаговая демонстрация Дейкстры на графе из восьми вершин. Вершины выбираются в порядке S, B, C, A, E, D, T. До U пути нет.

??? question "Из A выходит только дуга в D. Почему после A выбираем E?"
    После обработки A у D оценка 8, а у E уже есть оценка 7. Минимум ищем среди всех необработанных вершин с конечной оценкой.

??? question "Только что появилась оценка T = 15. Можно ли закончить?"
    Ещё нет. У D есть меньшая оценка 8. После выбора D путь через дугу D → T улучшит оценку T до 9. Для одной пары заканчиваем, когда выбираем T с минимальной актуальной оценкой.

??? question "Как повлияла дуга C → A веса 0?"
    При выборе C её расстояние равно 6. Переход стоит 0, поэтому получаем новое значение `dist[A] = 6 + 0 = 6` вместо 7.

## Почему можно зафиксировать расстояние { #why }

Представьте, что мы выбрали `v`, но до неё есть путь дешевле записанного в `dist[v]`. Посмотрим, где этот путь впервые выходит из обработанной части графа. На границе успели бы найти оценку ещё меньше, чем у `v`. Тогда алгоритм выбрал бы другую вершину.

??? abstract "Доказательство по шагам"
    1. Каждая конечная оценка — вес действительно найденного маршрута. Старт выбираем первым, его расстояние 0. Дальше считаем, что уже зафиксированные расстояния верны.
    2. Пусть при выборе `v` существует путь до `v` веса меньше `dist[v]`. Обозначим через `x` первую ещё не обработанную вершину на этом пути, через `y` — её предшественника.
    3. Вершину `y` уже обработали. Её точное расстояние не больше веса части пути до `y`. Когда проверили дугу `y → x`, оценка `x` стала не больше веса части пути до `x`.
    4. Оставшиеся рёбра имеют вес ≥ 0. Поэтому вес части пути до `x` не больше веса всего пути до `v`. Значит, `dist[x] < dist[v]`, что противоречит выбору минимума.

    Если больше нет конечных оценок у необработанных вершин, то достижимых среди них тоже нет. Иначе на пути к одной из них нашлась бы такая же первая необработанная вершина с конечной оценкой.

!!! warning "Что меняется при отрицательном весе"
    Пусть `S → T` весит 2, `S → A` весит 5, а `A → T` весит −4. После S алгоритм выберет T и зафиксирует 2. Но путь через A весит 1. Здесь начало маршрута до A дороже, чем весь маршрут. При нулевых весах такого эффекта нет.

## Как восстановить путь { #path }

В задаче «Путь» из первого дня мы записывали `par[v]`, когда BFS впервые находил вершину. В Дейкстре записываем предшественника при **каждом строгом улучшении**. В большом примере предшественник T сначала E, затем D.

Если путь существует, идём от T по `par` до S. Получаем `T, D, A, C, B, S`. После разворота это `S → B → C → A → D → T` веса 9. Если нужно вывести номера конкретных дуг, вместе с предшественником запоминаем номер дуги, по которой пришли.

??? question "Как выглядит маршрут, если старт и финиш совпадают?"
    В списке вершин одна вершина, рёбер нет, суммарный вес 0. Формат вывода зависит от условия.

??? question "Почему при равном весе можно оставить старый предшественник?"
    Старый маршрут уже имеет такой же вес. Если требуется любой кратчайший маршрут, менять его не нужно.

## Две реализации на C++17 { #code }

Обе программы читают `n m s t`, затем `m` ориентированных рёбер в формате `u v w`. Если путь есть, печатают его вес и последовательность вершин. Если пути нет, печатают `-1`.

Для примеров возьмём `n ≤ 200 000` и `0 ≤ w ≤ 10⁹`. Для сумм нужен `long long`. Неотрицательные веса позволяют выбрать кратчайший путь не более чем из `n − 1` рёбер. Даже с ещё одним ребром значение при релаксации не превысит `n · 10⁹`. Поэтому `INF = 1LL << 62` больше всех таких значений, и сложение не переполнится.

### Линейный поиск минимума

Перебираем все вершины, чтобы выбрать необработанную вершину с наименьшим расстоянием. Помечаем её в `used` и проверяем её исходящие рёбра. Поиск минимума выполняется не больше `n` раз и каждый раз занимает `O(n)`. Исходящие дуги каждой вершины просматриваются один раз, когда выбрана эта вершина.

### Как Дейкстра использует очередь с приоритетом

У `std::priority_queue` по умолчанию в корне находится наибольший элемент. С `greater<Entry>` в корне находится наименьшая пара `{расстояние, вершина}`. Сравнивается сначала расстояние, а при равенстве — номер вершины. `top()` читает пару из корня, `pop()` удаляет её. При улучшении добавляем новую пару, а старая может остаться в куче.

На шаге из C оценка A меняется с 7 на 6. Обе записи `{7, A}` и `{6, A}` могут лежать в очереди. Достав `{7, A}`, увидим, что `7 != dist[A]`, и пропустим запись. Проверку финиша делаем после этой проверки.

Чтобы найти расстояния от `s` до **всех** вершин, уберите досрочный выход по `v == t` и используйте весь массив `dist`.

### Как выбрать реализацию

Пусть `V` — число вершин, `E` — число рёбер. В коде это `n` и `m`.

| Алгоритм | Когда подходит | Время от одного старта до всех вершин |
| --- | --- | --- |
| BFS | Все рёбра имеют единичный вес | `O(V + E)` |
| Дейкстра с перебором | Неотрицательные веса, небольшой или плотный граф | `O(V² + E)` |
| Дейкстра с двоичной кучей | Неотрицательные веса, большой разреженный граф | `O(V + E log(E + 1))` |

**От одного старта до всех вершин (one-to-all).** Инициализация массивов и просмотр списков смежности требуют `O(V + E)`. Каждое ребро из обработанной вершины проверяем один раз, поэтому успешных релаксаций не больше `E`. Каждая добавляет в кучу одну запись. Вместе со стартом получаем не больше `E + 1` вставок и столько же извлечений. У одной вершины могут быть и актуальные, и устаревшие записи. Поэтому в этой реализации считаем операции по числу рёбер. В простом графе `E ≤ V²`, поэтому часто записывают более привычную оценку `O((V + E) log V)`.

**Между всеми парами (all-to-all).** Если запустить Дейкстру из каждой вершины, выполняем `V` таких проходов. Граф читаем один раз и используем те же списки смежности. Для двоичной кучи суммарно получаем `O(V² + VE log(E + 1))`.

**Когда получаются `O(V log E)` и `O(V² log E)`.** Это оценки для разреженного графа, в котором `E = O(V)`. При `E ≥ 2` можно подставить `E = O(V)` перед логарифмом, и получатся эти две формулы. В плотном графе рёбер порядка `V²`, и при оценке времени их приходится учитывать.

Память на один запуск обеих реализаций — `O(V + E)`. Если сохранить все расстояния между парами, матрица ответов дополнительно займёт `O(V²)` памяти.
