## Локальная сборка и просмотр

Для сборки нужен uv. Из корня репозитория запустите одну команду. Она подготовит окружение Python 3.12 по `uv.lock`, соберёт занятия и создаст общую страницу в `_site/`. [Установка uv](https://docs.astral.sh/uv/getting-started/installation/)

```bash
uv run --locked --python 3.12 python scripts/build_pages.py _site
```

В выводе сборки для каждого опубликованного занятия должна быть строка `page: …`. Например, второй день попадёт в `_site/2026/session-4/lecture-2/index.html`.

Чтобы проверить интерактивные демонстрации, поднимите HTTP-сервер из корня репозитория. Лекция на Zensical загружает JS-модули, которым нужен HTTP при локальном просмотре.

```bash
uv run --locked --python 3.12 python -m http.server 8000 --bind 127.0.0.1 --directory _site
```

Откройте [главную страницу](http://127.0.0.1:8000/) или [лекцию второго дня](http://127.0.0.1:8000/2026/session-4/lecture-2/). После изменений пересоберите сайт и обновите страницу. Для остановки сервера нажмите `Ctrl+C` в его терминале.

### Сборка отдельного занятия

Команды ниже можно запускать из корня репозитория. Результат каждой лежит в `docs/` соответствующего занятия, а общая главная страница создаётся при сборке всего сайта.

```bash
python3 2026/session-4/lecture-1/scripts/build_site.py
uv run --locked --python 3.12 python 2026/session-4/lecture-2/scripts/build_site.py
```

Версия Zensical задана в [`pyproject.toml`](pyproject.toml). Если меняете зависимости сборки, запустите `uv lock` из корня и закоммитьте обновлённый [`uv.lock`](uv.lock) вместе с `pyproject.toml`.

## Как добавить свои материалы

Каждое занятие лежит в своей папке `<год>/session-<смена>/lecture-<занятие>/`. Что и как внутри неё устроено, решает автор, но для публикации есть общие правила.

### Публикация страницы

- **Всё, что лежит в папке `docs/` с файлом `index.html`, публикуется автоматически.** Папка `<путь>/docs/` после push в `main` открывается по адресу `https://dx-by-dy.github.io/intellect/<путь>/` и попадает в общий список страниц. Workflow для этого менять не нужно.
- **Если страница собирается из исходника, `docs/` можно не коммитить.** Положите в папку занятия скрипт `scripts/build_site.py`, который пишет `docs/`, и добавьте `docs/` в `.gitignore` занятия. Перед деплоем общий сборщик запускает этот скрипт из папки занятия на Python 3.12. Скрипт использует стандартную библиотеку. Внешние инструменты сборки задаются в `pyproject.toml` и `uv.lock`. Например, Zensical преобразует `lecture-2/content/` в `lecture-2/docs/`. Если скрипт падает, общий сборщик пропускает страницу и выводит ошибку в Actions.
- В `docs/` кладите только готовую страницу для учеников: собранный HTML, стили, картинки. Не кладите туда черновики, решения и заметки для преподавателя, а если нужна другая документация, назовите папку иначе. Учтите, что сам репозиторий публичный, и ученики видят всё, что в нём лежит, а не только `docs/`.
- **Ссылки только относительные:** `style.css`, `img/graph.png`, `../lecture-2/`. Сайт живёт не в корне домена, а в `/intellect/<путь>/`, поэтому ссылка вида `/style.css` поведёт не туда.
- Файлы в UTF-8.
- Не кладите в `docs/` тяжёлые файлы (видео, архивы): лимит на весь сайт — 1 ГБ. Видео лучше выложить отдельно и дать ссылку.
- Папка `docs/` в корне репозитория и папки, имя которых начинается с `.` или `_`, не публикуются.

### Подписи на главной странице

Главная https://dx-by-dy.github.io/intellect/ собирается автоматически: страницы группируются по году и смене и показываются карточками. Папки вида `session-5` и `lecture-2` подписываются «Смена 5» и «Занятие 2», заголовок карточки берётся из `<title>` страницы, описание — из `<meta name="description">`.

Чтобы поменять подписи, добавить описание смены или карточку со ссылкой наружу (например, на отдельный репозиторий курса), отредактируйте [`site.toml`](site.toml): формат описан в комментариях внутри файла. Если в нём ошибка, деплой не сломается: сайт соберётся с подписями по умолчанию, а в Actions появится предупреждение.

### Если страница не появилась

Workflow [Deploy Pages](.github/workflows/pages.yml) запускается при push в `main` или вручную во вкладке Actions. В настройках репозитория в разделе **Pages → Source** должен быть выбран **GitHub Actions**. Workflow собирает `_site/` той же командой, что и локально. Перед загрузкой артефакта он проверяет наличие обеих лекций о графах и JS второго дня.

Чтобы найти причину, откройте последний запуск Deploy Pages во вкладке Actions. Проблемы конкретной страницы показаны как предупреждения и ошибки с путём к файлу. Общий сборщик может завершиться успешно, даже если пропустил отдельное занятие.

- `page ... skipped: ... collides with page ...` — файлы двух страниц попадают по одному адресу. Обычно так бывает, когда в `a/docs/` есть подпапка `b/`, и при этом существует `a/b/docs/`. Переименуйте одну из папок.
- `page ... skipped: not a regular file` — в `docs/` лежит битая символическая ссылка или не обычный файл.
- `page ... skipped: scripts/build_site.py exited with code ...` (или `timed out`) — скрипт сборки занятия завершился с ошибкой или превысил лимит в 5 минут. В сообщении есть последние строки вывода. Повторите сборку занятия локально, чтобы увидеть вывод целиком.
- `root-absolute link` — в странице есть ссылка, начинающаяся с `/`. Страница опубликована, но эта ссылка не откроется.
- `not valid UTF-8` — страница опубликована, но русский текст может отображаться неправильно.

Скрипты в `scripts/` в корне репозитория и `.github/workflows/pages.yml` общие для всех страниц. Не меняйте их, не договорившись с владельцем репозитория.
